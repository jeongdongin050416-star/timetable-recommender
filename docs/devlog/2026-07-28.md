Flyway는 "데이터베이스 구조 변경 내역(SQL 파일)을 코드처럼 버전별로 관리하고, 서버가 켤 때
알아서 순서대로 DB에 적용해주는 도구"이다. 간단히 말하면 데이터베이스의 버전 관리 도구이다.
Flyway는 어떻게 동작할까?
1. src/main/resources/db/migration에 SQL 파일을 버전 순서대로 만듦
2. spring boot 서버가 켜질 때 Flyway가 작동하여, 현재 DB에 어디가지 적용되었는지 확인하고
아직 적용되지 않은 최신 SQL파일들을 순서대로 실행함.
3. DB내부에 flyway_schema_history라는 특별한 테이블을 만들어서 어떤 버전이 성공적으로 적용되었는지 DB내부에 기록을 남김.
중복으로 실행되거나 순서가 꼬이는 것을 방지하기 위함임
flyway:
  enabled: true 역할: db table을 만들고 수정하며 관리하는 작업을 flyway보고 하라는 뜻
반면에 Hibernate는 java entity와 db table구조가 같은지 검사만함.

Java 파일 속 @Something은 Java의 annotation이다.
클래스, 메소드, 필드 등에 붙이는 부가 정보 또는 표식이다.
annotation 자체가 일반적인 method 호출처럼 바로 코드를 실행하는 것은 아니며,
컴파일러나 Spring, Hibernate 같은 프레임워크가 그 정보를 읽고 특별한 처리를 해줌.
annotation 마다 읽는 주체가 다름
예시:

@SpringBootApplication
@Configuration
@Bean
@RestController
@GetMapping
→ 주로 Spring이 읽음

@Entity
@Table
@Id
@Column
@ManyToOne
→ JPA/Hibernate가 읽음

@Override
→ Java 컴파일러가 검사

### Gradle이 Spring Boot를 실행시킬 때 Java 파일의 코드는 어떻게 실행되는가
1. Gradle 실행
2. Java 파일 컴파일
3. main() 실행
4. Spring Boot가 class와 annotation 조사
5. 필요한 객체와 설정 등록
6. 서버가 요청을 기다림
7. 요청이 들어오면 해당 method 실행

./grandlew bootRun을 실행하면 Gradle이 Java 파일을 컴파일하고, JVM이 TimetableRecommenderApplication.java의 main() method를 실행함.
./gradlew bootRun
        ↓
.java 파일을 .class로 컴파일
        ↓
TimetableRecommenderApplication.main()
        ↓
SpringApplication.run(...)
이런 과정으로 작동함
run 명령어가 작동되면 다음과정이 진행됨
SpringApplication.run()
        ↓
application.yml 읽기
        ↓
Spring이 관리할 클래스 탐색(탐색할 때 @SpringBootApplication이 붙은 클래스의 패키지를 기준으로 검색함. 그게 여기서는 com.example.timetablerecommender이므로 그 아래의 config, web, domain 패키지를 탐색함)
        ↓
설정 객체와 Controller 객체 생성
        ↓
DB 연결과 Hibernate 초기화
        ↓
HTTP 주소와 메서드 연결
        ↓
웹 서버 실행
        ↓
요청 대기

Spring Boot 프로젝트에서 이 네 가지를 구분해야함.
1. 클래스가 compile됨
2. 클래스가 Spring에 의해 발견됨
3. 해당 클래스의 객체가 생성됨
4. 특정 method가 실제 호출됨

예를 들어 HealthController.java는 컴파일되지만, 서버 시작 시 health() method가 자동으로 실행되지는 않음
health() method는 GET /api/health 요청이 들어올 때 실행됨.

서버가 시작될 때 Spring이
HealthController 발견
    ↓
HealthController 객체 생성
    ↓
GET /api/health와 health() 메서드 연결
해줌 하지만 이 때 health()를 실행하지는 않음 health()는 요청이 들어온 뒤에 실행함.
클라이언트가 GET /api/health 요청
        ↓
SecurityFilterChain 통과
        ↓
Spring이 연결된 메서드 검색
        ↓
HealthController.health() 실행
        ↓
Map 반환
        ↓
JSON 변환
        ↓
{"status":"ok"}

entity class도 서버 시작 시 발견되지만, 엔티티 안의 모든 method가 자동 실행되는 것은 아님.
Spring과 Hibernate가 entity의 annotation을 읽어서 매핑 정보(클래스 - 테이블)를 만들고 그 뒤 Repository나 EntityManager로 DB를 조회할 때 Hibernate가 실제 객체를 만듦.

SpringBoot 특징: 복잡하지만, 프로젝트가 커졌을 때 구조, DB, 보안, 트랜잭션, 테스틀 일관된 방식으로 관리할 수 있음
장점: 
1. 서버를 빠르게 만들 수 있음
2. 복잡한 설정을 자동으로 처리함
3. 계층 구조를 표준화하기 좋음
4. DB 코드를 줄일 수 있음
5. transaction 처리가 편함
6. 보안 기능이 강함
7. 대규모 프로젝트에 적합함
8. 테스트하기 좋음
9. 생태계가 매우 큼
