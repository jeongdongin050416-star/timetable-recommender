## Gradle

Gradle은 Spring Boot 백엔드를 준비하고 실행하는 빌드 도구이다. 이 프로젝트에서
Gradle은 Java 백엔드를, Docker Compose는 PostgreSQL 서버를 담당한다.

`./gradlew bootRun`의 주요 흐름:

1. `build.gradle`을 읽고 필요한 Java 라이브러리를 준비한다.
2. `backend/src/main/java` 아래의 `.java` 파일을 재귀적으로 찾아 컴파일한다.
3. `application.yml` 같은 리소스를 실행 결과에 포함한다.
4. JVM이 `TimetableRecommenderApplication.main()`을 실행한다.
5. Spring Boot가 시작되고 8080 포트에서 요청을 기다린다.

현재 백엔드는 Spring Boot, Hibernate, PostgreSQL 드라이버, Flyway 등의 외부
라이브러리가 필요하며 `backend/build.gradle`의 `dependencies`에 선언되어 있다.

관련 파일:

- `settings.gradle`: Gradle 프로젝트 이름 지정
- `gradlew`: Linux, macOS, WSL용 Gradle Wrapper 실행 스크립트
- `gradlew.bat`: Windows 명령 프롬프트와 PowerShell용 실행 스크립트
- `TimetableRecommenderApplication.java`: 백엔드 시작점
- `config/SecurityConfig.java`: Spring Security 설정
- `web/HealthController.java`: `GET /api/health` 요청 처리

## 애너테이션

Java의 `@Something`은 클래스, 메서드, 필드 등에 붙이는 부가 정보 또는 표식인
애너테이션이다. 애너테이션 자체가 일반 메서드처럼 즉시 실행되는 것은 아니며,
컴파일러나 프레임워크가 읽고 특별한 처리를 한다.

- Spring: `@SpringBootApplication`, `@Configuration`, `@Bean`,
  `@RestController`, `@GetMapping`
- JPA/Hibernate: `@Entity`, `@Table`, `@Id`, `@Column`, `@ManyToOne`
- Java 컴파일러: `@Override`

## Spring Boot 실행 흐름

```text
./gradlew bootRun
        ↓
.java 파일을 .class 파일로 컴파일
        ↓
TimetableRecommenderApplication.main()
        ↓
SpringApplication.run(...)
        ↓
application.yml 읽기
        ↓
하위 패키지의 구성 요소와 엔티티 탐색
        ↓
설정·Controller 등록, DB 연결, Flyway·Hibernate 초기화
        ↓
내장 웹 서버 실행 후 요청 대기
```

`@SpringBootApplication`이 있는 `com.example.timetablerecommender` 패키지가 탐색
기준이므로 그 아래 `config`, `web`, `domain` 패키지가 범위에 포함된다.

Spring Boot에서는 다음 단계를 구분해야 한다.

1. 클래스가 컴파일된다.
2. Spring 또는 Hibernate가 클래스를 발견한다.
3. 필요한 클래스의 객체가 생성되거나 매핑 정보가 등록된다.
4. 특정 메서드가 실제 호출된다.

예를 들어 서버 시작 시 `HealthController`를 발견하고 객체를 만든 뒤
`GET /api/health`를 `health()`에 연결하지만, 이때 `health()`를 실행하지는 않는다.

```text
클라이언트가 GET /api/health 요청
        ↓
SecurityFilterChain 통과
        ↓
Spring이 연결된 메서드 검색
        ↓
HealthController.health() 실행
        ↓
Map 반환
        ↓
JSON 변환
        ↓
{"status":"ok"}
```

엔티티도 서버 시작 시 발견되지만 모든 메서드가 자동 실행되는 것은 아니다. Hibernate는
애너테이션으로 클래스와 테이블의 매핑 정보를 만든다. 이후 Repository나 EntityManager로
DB를 조회할 때 실제 엔티티 객체를 만든다.

## Flyway와 Hibernate

Flyway는 DB 구조 변경 내역을 SQL 파일로 버전 관리한다.

1. `src/main/resources/db/migration`에 버전 순서의 SQL 파일을 만든다.
2. 서버 시작 시 현재 DB에 적용된 버전을 확인한다.
3. 아직 적용하지 않은 SQL을 순서대로 실행한다.
4. `flyway_schema_history`에 성공한 마이그레이션을 기록해 중복 실행과 순서 꼬임을 막는다.

`spring.flyway.enabled: true`는 Flyway 마이그레이션을 활성화한다. 이 프로젝트에서는
Flyway가 DB 구조(DDL)를 관리하고, Hibernate는 Java 엔티티와 DB 테이블 구조가 일치하는지
검증하며 객체와 데이터 사이의 변환을 담당한다.

## Spring Boot의 장점

1. 서버를 빠르게 구성할 수 있다.
2. 복잡한 설정을 자동화한다.
3. 계층 구조를 일관되게 만들기 좋다.
4. DB 접근 코드를 줄일 수 있다.
5. 트랜잭션 처리가 편리하다.
6. 강력한 보안 기능을 제공한다.
7. 대규모 프로젝트에도 적합하다.
8. 테스트하기 좋다.
9. 생태계가 크다.
